## 0. 一页结论

截至2026年8月18日，项目已经完成了三件彼此不同的工作：

1. **小规模 controlled multi-future 数据构造管线已经跑通。**现在有两个真正独立、机器验收通过的 root groups：`g_000007`和`g_000008`。每组包含3个结构化意图，每个意图有2条真实成功轨迹，因此共有12条正式 raw trajectories。
2. **第一次 tiny model 机制诊断已经完成，但核心 Gate 没有通过。**模型看到完整未来动作时，准确率从current-only的33.3%提升到53.3%；但endpoint-only也是53.3%，严格future replacement后的prediction-switch为0%。这说明当前模型主要使用轨迹终点，没有学会共享前缀刚结束时的微小分叉信号。
3. **12条formal trajectories均已有可直接观看的四视角MP4。**视频及逐条receipt/contact sheet位于上述可视化目录；它们用于人工查看记录状态，不改变formal raw，也不进入模型训练。

因此，当前最准确的阶段描述是：

> 数据构造 pipeline acceptance 已完成；第一次 WP-G0 小模型实验已执行并留下完整证据；raw future 存在可利用信号，但“模型真正根据替换后的未来动作切换意图预测”的核心机制尚未成立。

当前没有进入大规模扩数、系统性`H_reveal`、动作压缩、π0.5训练或策略迁移。下一步应先在现有两组数据上做版本化的suffix-horizon和delta-aware模型诊断，而不是立即继续采数据或重复训练同一个模型。

## 1. 研究问题与本阶段边界

本项目研究的是：在某个anchor时刻`t`，给定相同的当前观测、当前机器人状态，以及从`t`开始的一段未来动作，能否判断机器人接下来要完成哪个结构化行为程序：

```text
current observation o_t
+ current robot state s_t
+ future action a[t:t+H]
                    ↓
structured intent / ordered operation program
```

这里的intent不是心理动机，也不是简单的“往左/往右”，而是可由模拟器验证的程序，例如：

```text
place(mouse, on_surface_of, gray_pad)
place(mouse, on_surface_of, electronic_scale)
place(mouse, on_surface_of, display_stand)
```

未来动作只是训练与诊断阶段的privileged evidence。正常策略部署仍然是：

```text
current observation + current robot state + normal instruction -> action chunk
```

本阶段也不把future replacement表述成“未来动作在物理上导致意图”。它只检验：current固定时，将真实future A替换为同组真实future B，并同步将监督目标换成intent B，模型预测是否随输入变化。

## 3. 构造的数据到底是什么样

### 3.1 基本单位不是一条trajectory，而是一个root group

一个合格root group的结构是：

```text
一份联合场景：mouse + gray pad + electronic scale + display stand
                         ↓
一份共享的current context和物理等价anchor
                         ↓
冻结三个可行candidate programs
              ┌──────────┼──────────┐
              ↓          ↓          ↓
          mouse→pad  mouse→scale  mouse→stand
              ↓          ↓          ↓
         r_pc + r_inv r_pc + r_inv r_pc + r_inv
```

这里：

- `M=3`：同一current下有3个可行的结构化意图；
- `R=2`：每个意图有2条真实成功实现；
- `r_pc`：三个意图共享字节/数值一致的canonical approach-grasp-lift prefix，用于严格的H/P比较；
- `r_inv`：同一意图的独立planner/controller path，用来检查模型是否只记住某一条路径指纹；
- `P=1154 steps=4.616 s`：三个`r_pc`分支在primary future stream上完全一致的公共前缀；
- 每个物理step为`0.004 s`，即250 Hz。

### 3.5 current context如何保证“同一个现在”

每个root只定义一份current context，六个branch的receipt共同hash绑定它，而不是每条轨迹各拍一张“看起来差不多”的图。current evidence包括：

- `head/front/left/right`四个相机的RGB，均为`240×320×3 uint8`；
- 每个相机的calibration；
- anchor时刻的12维controlled qpos、12维qvel和2维realized gripper state；
- scene topology、canonical physical/contact hash和source lock。

组内六条branch的current RGB array hash和state index 0必须相等。g7与g8是两个不同root，因此它们彼此的current不同，这正是leave-one-root-out诊断需要控制的统计层级。

## 4. 从raw派生出来的训练/评测view

派生层不复制动作数组，只保存对immutable raw的引用、切片边界、slice hash、目标和可见性合同。

每个root有36个views：

- 30个natural-H views；
- 6个future-replacement views。

30个natural views的组成是：

- 六条branch都具有`H={0,1,2,full}`，共24个；
- 三条`r_pc` branch额外具有`H=P`和`H=P+1`，共6个。

6个replacement views是三个`r_pc` intent之间的有向替换，固定在`H=P+1=1155 steps`，并同步切换监督目标。例如：

```json
{
  "view_type": "future_replacement",
  "H_steps": 1155,
  "original_intent_id": "i_000001",
  "replacement_intent_id": "i_000002",
  "target_intent_id": "i_000002",
  "target_synchronously_changed_with_future": true,
  "compatible_set_model_visible": false
}
```

两个root合计72个views。三个candidate的六种排列全部物化，因此adapter共验证432个permuted materializations，target display positions严格平衡。

在`H<=P`时，三个intent仍共享完全相同的可观察未来，监督不能强行给branch one-hot；loss使用observable compatible set。只有`H>P`且compatible set成为singleton时，才计算branch-specific Top-1和replacement-switch。

## 6. 小模型是怎么训练的

### 6.1 任务形式

任务是同组candidate retrieval/ranking。模型同时看到三个structured programs，用同一个shared candidate-conditioned scorer分别打分。禁止使用固定三分类head，也禁止把candidate ID或显示位置送进网络。

### 6.2 模型结构

模型版本为`wp_g0_tiny_shared_scorer_v1`，共45,025个参数：

- candidate encoder：把canonical text和structured semantic program编码成39维对称token vector；
- current-state encoder：读取12 qpos + 12 qvel + 2 realized gripper；
- future encoder：读取26维raw future、6维update mask和2个timestamps，使用两层temporal Conv，再做masked mean/max/last汇聚；
- shared scorer：每个candidate通过同一个`out_features=1`打分头。

视觉端本轮明确设为`interface_zero_no_weights`。没有下载或训练视觉backbone，因此`current_state_correct_future`实际复用no-vision checkpoint，本轮不能作visual grounding结论。

### 6.3 训练设置

| 项目 | 设置 |
| --- | --- |
| whole-root folds | train g7/test g8；train g8/test g7 |
| model seeds | 2026081801、2026081802、2026081803 |
| epochs | 60 |
| optimizer | AdamW |
| learning rate | 0.002 |
| weight decay | 0.0001 |
| gradient clip | 1.0 |
| hidden dim | 48 |
| train views | 每个train root的15个singleton views |
| candidate order | 三候选六种排列循环，位置严格5/5/5平衡 |
| checkpoint | 固定最后一轮；无validation、无early stopping、无test选择 |
| hyperparameter search | 无 |

实际训练的checkpoint variants有5个：

```text
candidate_only
current_state_only
future_only
state_future_no_vision / current_state_correct_future
current_state_endpoint_only
```

replacement和temporal shuffle作为同一primary raw-future checkpoint的评测变换。总计：

```text
2 folds × 3 seeds × 5 checkpoints = 30 checkpoints
```

实验只在fresh-idle physical fvl05 GPU0上运行一次，GPU UUID为`GPU-2c620e6c-9639-2022-b573-9847dfa33769`。训练与评测耗时约141.565秒；wrapper记录child PID/PGID、pre/post snapshot和完整closure。运行后GPU0回到14 MiB、0% utilization、P8、无compute process。

## 7. 小模型得出了什么结果

### 7.1 冻结指标

| 指标 | 六个fold-seed均值 | 解释 |
| --- | ---: | --- |
| current-only singleton Top-1 | 33.3% | 三候选chance baseline |
| correct raw future Top-1 | 53.3% | 比current-only高20个百分点 |
| endpoint-only Top-1 | 53.3% | 与完整raw future完全相同 |
| raw minus endpoint | 0.0 | temporal sequence未超过终点 |
| replacement target accuracy | 33.3% | replacement后仍是chance |
| strict replacement prediction-switch | 0.0% | 核心hard Gate失败 |
| same-intent cross-trajectory consistency | 100% | 一致性Gate通过 |
| candidate permutation score delta | 0 | 排列等变Gate通过 |

分fold看：

- train g7 → test g8：三个seed的raw future accuracy均为60%；
- train g8 → test g7：三个seed均为46.67%；
- 两个方向的current-only都为33.33%；
- 六个seed的strict replacement-switch全部为0。

### 7.2 为什么判失败，而不是说“53.3%比33.3%高，所以成功”

raw future确实带来了方向性增益，但endpoint-only获得完全相同的分数。更重要的是，把future A换成future B并同步切换target以后，模型一次都没有按新future切换预测。

因此，当前模型更像是在使用“轨迹最后走到了哪里”，而不是理解“共享prefix之后动作如何开始指向另一个程序”。预注册Gate要求strict replacement-switch至少为50%，实际是0%，所以overall pipeline smoke必须判`false`。

### 7.3 额外read-only定位

对六个primary checkpoints做了不更新权重的posthoc复评：

| 评测 | 六个checkpoint结果 |
| --- | ---: |
| train-root full-natural accuracy | 100% |
| train-root `P+1` natural accuracy | 33.3% |
| train-root `P+1` replacement accuracy | 33.3% |

`P+1`只比公共prefix多一个250 Hz step，即4 ms。同root三个branch在第一个分叉action上的两两L2只有约0.008448～0.015774，而跨root offset约0.114。

这说明失败不只是“跨root泛化不够”：模型在自己的train root上也没有学会那一个很小的首次分叉增量。冻结的tiny temporal encoder/优化过程能拟合完整轨迹终点，却忽略最短suffix。

### 7.4 当前可以和不可以下的结论

可以下的结论：

1. controlled multi-future的raw-first数据构造、验证、派生和跨版本读取管线已经跑通；
2. full future action中存在可用于区分意图的信息；
3. 当前tiny model主要利用endpoint，最短suffix表示能力不足；
4. candidate位置、长度、简单event和planner/path metadata没有形成已发现的捷径。

不能下的结论：

1. 不能说future action mechanism已经成立；
2. 不能把53.3%当作正式泛化结果；
3. 不能估计可靠的`H_reveal`；
4. 不能声称视觉grounding已验证；
5. 不能进入compression、π0.5或policy-transfer结论；
6. 不能把72个derived views当作72个独立统计样本。

真正独立的统计单位只有两个root groups，即有效`N=2`。这些数据足以做pipeline smoke、overfit检查和双向leave-one-root-out诊断，但不足以支持正式显著性、稳定方差或论文级泛化结论。

## 9. 下一步建议

下一阶段应另起版本，不覆盖`run_000001`：

1. 在现有g7/g8 immutable raw上建立更细的suffix-horizon grid，不只比较`P`和`P+1`，而是观察分叉后4 ms、8 ms、16 ms、事件级窗口直到full；
2. 显式构造相对公共prefix末端的action delta、velocity delta、方向和尺度归一化特征，避免跨root绝对offset压过组内分叉；
3. 使用同一个正式adapter/entrypoint，重新验证candidate permutation、same-intent invariance和replacement-switch；
4. 先在train root证明模型能学到短suffix，再检查leave-one-root-out；
5. 只有replacement和cross-trajectory Gate通过，才扩充更多独立roots，并尽量达到每intent `R>=3`；
6. 更多root上的raw-future value通过后，再系统寻找`H_reveal`；之后才讨论K/compression，最后才是π0.5。

这一步优先是模型/表示审计，不需要立刻重新采集formal raw，也不应通过暗增epoch、seed或重复GPU run来覆盖本次失败。
