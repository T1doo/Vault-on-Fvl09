# Unexecuted collector Gate integration correction and pending decision

Status: **NO FLOOR-PAIR PROJECTION ENABLED OR IMPLEMENTED IN THE ENTRY**.
The proposal below is not covered by the previous geometry approval. A
transient unpublished CPU draft existed before the main-thread pause arrived;
it was removed without running it. The actual transport module passes every
original row directly into the original auditor.

The first CPU implementation omitted the old F2 whole-held-window contact
Gate and two final family checks; it was not GPU qualified. It must not be
described as having preserved every original Gate before this correction.

`family_runners_v3_3.py` calls `audit_f2_held_transport_contacts` over every
held row, requiring selected-contact continuity, selected actor identity and
no unintended body contact. For old gravity-drop inside it forbids all held
support; that assumption conflicts with explicitly approved supported
controlled insertion. Merely passing the last 50 support frames is not an
equivalent replacement.

The proposed, not implemented, narrow adapter would retain the original audit and its result
over immutable original rows. During lift/preinsert it uses that result
unchanged. Only after the actual controlled-descend trace boundary may a
can/box pair be projected out of a separate audit input, and only if the
actual row passes the approved native-floor contact verifier, both shape
identities resolve to the actual registry, its box shape is exactly box__9,
and its original V8 physical-hit evidence passes. Every projected pair gets
an explicit row/pair and proof receipt. The original audit then checks the
projected rows, retaining all original continuity/identity and other-body
rules. It never receives a blanket box support whitelist. Sidewalls, other
floor pieces, unknown/incomplete contacts and contacts before descent remain
rejected. This is a documented adaptation of the old no-held-support
assumption to the already-approved real-floor controlled insertion, not a
claim that the original inside support rule passed unchanged.

The final controller also preserves the original `_stable_and_support`
50-frame object linear/angular/support checks and the original final EEF
linear/angular stationary checks. The original family orientation metric is
1−abs(quaternion dot)≤.02; the older controlled-insertion rest additionally
uses angular error≤.02 rad. Both original checks are retained. No new
per-segment numeric tracking threshold is invented: old F2 segment helpers
reported tracking, whereas the explicit per-segment tracking hard Gate found
in the source belongs to F3. New `execute_one.pass` is a real transport-Gate
result, not an unconditional success flag. Currently that result is the
unmodified original Gate and rejects genuine can/box9 held contact.

## No legal phase-only workaround

The original source creates held_transport_start_row before the first carried
segment and takes all rows through release_index, including the entire final
descent. The audit runs before opening. A can supported by the floor while
still gripped therefore genuinely appears in that window. Renaming phases,
ending the window before first contact, or dropping descent/support rows
would change the Gate by omission; none is implemented. Keeping the original
whole window and predicate is possible, but then controlled inside cannot
pass. A supported-contact exception needs an explicit narrow decision,
retaining old failures and versioning the changed verification semantics.
Numerical thresholds and every noncertified pair must remain unchanged.
