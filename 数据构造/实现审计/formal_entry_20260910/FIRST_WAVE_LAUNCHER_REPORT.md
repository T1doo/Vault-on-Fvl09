# First-wave launcher — CPU implementation

`first_wave_launcher.py --manifest MANIFEST --state-dir NEW_NAMESPACE` is a thin coordinator around existing `gpu.live_snapshot`, `guard_card`, `child_environment`, shared physical-GPU lease functions, and `ExecutionLedgerV2`. It does not read or mutate P2/P3/P4 ledgers. A nonempty foreign namespace is rejected before modification. A small namespace-binding journal permits interrupted initialization to resume safely.

The manifest fixes exactly `F1_000001` and `F1_000002`, independent job outputs, complete source pins, resolved specs, child authorizations, copy destinations, shared caps and GPU0–7. `execution_authorized=false` or either child authorization not granted prevents even a GPU snapshot. CPU preparation supplies no execution authorization.

After authorization, a real two-process NFS lock check precedes dispatch. A single coordinator owns state; ledger reserve/settle operations are serialized across its two worker threads. Each root receives one currently idle card. The existing canonical physical lease and an additional UUID flock are held during a fresh prelaunch Guard check. Busy GPU0 does not prevent dispatch onto idle GPU1–7; one available card is sufficient to run one ready root.

Each child runs the actual `execution_cli.py`, which collects, independently checks, and creates its required independent copy. The caller must source the sole environment entry `Robotwin2/config/activate_robotwin2.sh` before authorized host execution. The launcher explicitly uses the project interpreter, project CUDA/PATH, unset LD_LIBRARY_PATH, actual UUID, physical-index renderer binding, and isolated job cache/TMP directories. F1 now uses the existing pinned SAPIEN renderer context and records the renderer-to-Guard binding.

Owned PID/PPID/PGID/start-time trees are tracked. Cleanup signals target only recorded process identities; the child is reaped. The child end boundary is written before cleanup/usage parsing; the final lease boundary is written before usage parsing. Both child elapsed time and the full acquisition-through-release lease interval are retained. Snapshots use the existing implementation with a scoped 10-second subprocess timeout, without changing its globals or GPU policy.

The frozen resource allowance is 6500 seconds child timeout, 600 seconds cleanup, and 100 seconds pre/post/reap overhead within a 7200-second per-root lease reservation. Unexpected excess is recorded as BUDGET_OVERRUN and stops new dispatch. GPU reservation is not copied per thread or family. There are no automatic retries of failed launcher jobs; bounded native recovery requires explicit reconciliation under the same approved resource accounting.

Usage is read from the new native cohort and recovery root receipts. Created-scene cleanup records, prefix/reference/replay counters, created `strict_prefix_branch:` scene records and total planner counts are used. Collection attempts count a created branch scene even if capture/prefix fails before suffix execution; copied/reused branches create no scene and are not charged again. Missing phase or scene-created evidence leaves accounting unresolved. Those action counters increment before the attempted controller operations, so a partial failed prefix is charged. Missing terminal evidence leaves reservations unresolved. An ordinary CLI error with no native scene-entry evidence charges only the measured lease; it never charges the entire reservation as an exact measurement.

Successful exit is insufficient for PASS. The launcher reloads `execution_result.json`, the independent native root result, the root copy manifest and registry, then reads all nine copied packages and validates root/spec identities. Missing or failed evidence yields FAILED while known resource usage still settles. Synthetic fixtures cannot pass this production completion gate. Owned process/GPU PID residue yields UNRESOLVED with no claimed lease-release completion. An external post-run occupant only changes `device_idle_observed`; it does not invalidate proven owned cleanup.

Nine CPU tests passed: false authorization has zero snapshot calls; fake idle GPU1/2 dispatch; exact native accounting; measured CLI-error lease; unresolved reservation retention; partial failed-prefix accounting; zero-exit/missing-evidence rejection; owned compute-process residue; timeout bounds; and two-process locking (some checks share a test case). The positive fake scheduler test substitutes its disk-completion boundary explicitly; the separate F1 whole-CLI fixture tests exercise real independent disk verification and portable copying. No nvidia-smi call, CUDA initialization, renderer or physical job was executed by launcher tests.

Each frozen job now requires `spec_file_sha256` and `authorization_file_sha256`. The launcher hashes and parses the same bytes before loading, repeats the comparison before lease acquisition and immediately before the child call, and checks them again during completion verification. Updating a spec self-hash or changing an otherwise valid authorization cannot bypass the job manifest binding. Both mutation cases were rejected before any snapshot in the added CPU regression.
