# Portable v2 — CPU-only independent copies

The four-family adapters preserve source receipt bytes and bind the expected source-index file hash to source bytes and independently copied bytes. A copied index is mandatory. Modern cell/root finalizers bind cell identity, trace hash, root identity, scene spec and root membership. Legacy F1/F4 frozen candidate, anchor and prefix files are located through their original root directory, then checked against semantic hashes in the already indexed root/branch receipt; these hashes are recomputed again during package reading. Legacy finalizer evidence retains its original embedded form and historical development qualification.

The package-only reader separates inputs, supervision and audit. It checks exact receipt candidate set and target identity; state versus trace row0; finite robot state/future; camera names, dimensions and dtype; mandatory hashed supervision/prefix/anchor; duplicate roles; source/index correspondence. N-actions and N+1-with-placeholder are separate declared layouts. Legacy duplicate articulation storage is reduced only after exact equality of both 38-element halves. No synthetic observations or successful physical receipts are fabricated.

Each final sample includes the reader and reader contract in its file manifest. Subprocess tests load that bundled reader with access to original datasets, active project and Vault denied. Python and NumPy runtime files remain accessible. The four final packages reside under `/nfs_share/lijunhui/CVPR_FutureIntent_Data/formal_entry_20260910_samples/`; all intermediate copies and source data are preserved. Exact paths, byte counts, shapes and reader hashes are in `PORTABLE_RESULTS.json`. Reader hashes are recorded per package; a legacy F1 package retains its independently verified reader revision. This remains same-NFS independent physical storage, not offsite backup.

Root publication requires an exact 3-program by 3-realization Cartesian matrix, common root/spec/candidates/current/anchor, and strict prefix equality for the three r_pc cells only. It copies listed cell files into relative nested cell directories, validates the package before atomic rename, and registers it under a separate short registry lock. Root and staging names are unique; different-version collisions refuse overwrite. Retrying a published root revalidates its nested packages. No GPU or simulator code is imported.

Eight unittest methods cover interrupted copy, interruption before and after rename, interruption before registry update, same-version recovery, version conflict, missing supervision, row0/NaN/camera/target failures, both action schemas and a synthetic complete 3×3 root. The root fixture is explicitly synthetic and exercises storage only; it does not substitute for nine physically collected trajectories. Independent adversarial review is reported separately by the coordinator.

Limits: these four examples establish existing-source adaptation, not untouched-test eligibility or new physical validation. Formal eligibility remains false. The outer manifest/registry must be retained as a trusted integrity record; checksums do not constitute a digital signature against an attacker able to rewrite the entire index, package and registry. Disk free space is shared-volume availability, not a verified personal quota. No original data was moved or deleted.
