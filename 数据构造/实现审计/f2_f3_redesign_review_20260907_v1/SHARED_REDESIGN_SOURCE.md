# 二、F2 到底为什么停在盒子前？

## 1. 停止位置已经非常明确

原始记录显示：

```text

```

也就是说，机械臂完成了第一段搬运，随后规划器拒绝下一目标，所以没有再执行动作。**不是机器人已经伸进去卡住了，也不是成功录像被截掉了。**fileciteturn526file0L2-L2

## 2. 这个“插入前目标”本身就很不合理

从实际搬运终点到旧 preinsert 目标，代码要求：

```text
X 方向移动约 18.6 cm
Z 方向下降约 23.4 cm
姿态旋转约 179.8°
```

同时，原生几何检查发现：

```text
手掌 fl_link6 ↔ 桌面
手掌 fl_link6 ↔ 多个盒体碰撞片
手指 fl_link7 ↔ 盒壁
```

均存在交叠。即使把额外碰撞 buffer 去掉，问题也没有消失。fileciteturn526file0L2-L2

因此，这次的真正结论是：

> **不是再换一个中转点就能解决，而是旧“罐子放置姿态 + 小盒子 + 当前抓法”的组合，给出了一个夹爪无法合法占据的目标。**

旧 `spec.py` 仍然从历史 `saved_contact_geometry.json` 取目标姿态，并要求特定 `box__9` 支撑。它把一套历史几何选择直接带进了新执行器，而不是重新选择适合当前抓法的放置姿态。fileciteturn555file0L2-L2

## 3. 现有“大盒子候选”有价值，但还不应继续追求最小修改量

仓库已经推导了一个约 **1.1447 倍**的同类放大盒子，CPU 上的罐体、闭合手部和三厘米竖直插入必要条件通过。这个方向比继续翻转罐子合理。fileciteturn532file0L2-L2 fileciteturn540file0L2-L2

但它主要检查的是**闭合夹爪插入**，还没有证明：

```text
到达箱底后，夹爪能完整张开
→ 张开时不撞壁
→ 空手能够退出
```

而且旧盒子存在复杂分片和非简单平底，继续围绕它求最小放大量，可能又花大量时间处理底面、碰撞片编号和极限净空。

**你的目标是关系意图数据，不是“极限小容器插入”。没有必要守住这只旧盒子。**

# 三、F2 的新主方案：直立罐子，宽口平底盒，垂直放下

## 我的明确建议

**保留已经有真实正结果的直立抓罐思路，取消不必要的翻转，使用有充足操作余量的宽口、平底容器。**

流程应当是：

```text
抓住罐子并抬起
→ 保持罐子朝向
→ 搬到盒口上方
→ 垂直下降
→ 罐子底部获得真实支撑
→ 缓慢张开夹爪
→ 空手垂直退出
→ 回到安全位置
```

### 容器选择不再强制绑定旧 base2

新窗口可以按以下顺序选择：

**优先方案：能满足全部操作包络的现有宽口平底盒。**

**若现有盒子的复杂底面和碰撞分片继续成为主要障碍，直接构建一个参数化开口盒：一个底板、四个侧壁。**

这仍然是“放进盒子”，没有改变 F2 的研究语义。新容器必须有匹配的可视几何和碰撞几何，明确标记为项目自定义场景资产，不能假称未修改的官方资产。

不要把整个盒子做成一个实心凸包，否则内部空腔会被碰撞模型填满。

## 容器尺寸按完整操作计算，不按罐子单独计算

必须考虑四个包络：

```text
罐体
闭合夹爪与手掌
张开夹爪的扫掠空间
空手退出空间
```

不是“罐子能塞进去就够了”。

尺寸应满足：

- 罐体完整落在盒内，保留原侧壁与顶部成功标准。
- 罐底接触真实底板，而不是为了满足“六面内缩”要求悬在空中。
- 非预期接触处有足够余量，结合实际碰撞 buffer、contact offset 和跟踪误差确定。
- 释放过程中，手指不碰侧壁，掌部不碰盒沿。
- 盒子处在机械臂已验证的工作区内，不为了保留旧桌面坐标又放到难够的位置。

这里的“增加余量”是**改大容器、选好位置**，不是放宽成功阈值。

## 新目标只由当前真实抓持关系推导

设当前真实抓持变换为 \(T_{\text{EEF,can}}\)，目标罐体姿态为 \(T_{\text{world,can}}^\*\)，那么：

\[
T_{\text{world,EEF}}^\*
=
T_{\text{world,can}}^\*
\left(T_{\text{EEF,can}}\right)^{-1}
\]

不能继续从历史接触文件复制一个不适合新盒子的姿态，也不能在 IK 通过以后再修改姿态。

**新布局、新盒子、新目标都应生成新的 root/current/anchor。hash 改变是正常且必要的，不是需要避免的错误。**

# 四、F3：竖放方案值得采用，但先处理一处物理基线错误

## 1. 横放视频的实际失败不是“力气小到举不动”

对应最后一次横放记录：

- 抬升已经实际执行。
- 瓶子离开垫子。
- 两指持续接触。
- 最后五十帧中，相对位置和姿态持续变化。
- 最终相对漂移约 **6.06 mm / 0.0576 rad**，超过原标准。fileciteturn557file0L2-L2

这说明是**承重后的抓持不能维持**，不是单纯没有抓到，也不是上次那个支撑碰撞模型又拦住了。

两侧有接触并不保证能抵抗所有转动；接触位置、法向、摩擦以及接触斑能产生的力矩都会影响稳定性。citeturn438302search0

## 2. 新发现：质量、尺寸、惯量存在明显不自洽

仓库保存的实际物理属性是：

```text
质量：
0.0099999998 kg，约 10 g

主惯量：
0.0028761
0.0003455
0.0028816
单位：kg·m²

瓶体尺寸：
约 6.85 × 6.74 × 24.79 cm
```

这些不是我根据视频猜的，是 `f3_upright_design_v1/design_spec.json` 引用的实际刚体属性记录。fileciteturn536file0L2-L2

我按记录的包络与质心做了一个独立物理一致性检查。

物体全部质量若位于距质心最大半径 \(R\) 内，则任意轴惯量必然满足：

\[
I \le mR^2
\]

根据记录计算，保守最大半径约为 **0.1456 m**，因此：

\[
mR^2 \approx 0.0002120\ \text{kg·m}^2
\]

但两个实际记录的主惯量约为 **0.00288**，超过这个保守上界约 **13.6 倍**。

**按这些记录的单位、几何与质心，它们不可能同时描述同一只质量 10 克的瓶子。**

这不是惯量“稍微偏大”，而是必须优先查清的资产物理一致性问题。

## 3. 代码中已经找到很强的解释线索

锁定版本的 `Actor`：

```python
def __init__(..., mass=0.01):
    ...
    self.set_mass(mass)

def set_mass(self, mass):
    ...
    component.mass = mass
```

**这里只设置了质量，没有同步设置惯量。**而且默认包装 `Actor` 时就会执行一次。fileciteturn547file0L2-L2

PhysX 官方文档明确：`setMass()` 不会自动更新刚体惯量；质量、惯量和质心需要通过对应接口一致设置。SAPIEN 的实现也将 `setMass` 与 `setInertia` 分开。citeturn902957view0 fileciteturn550file0L2-L2

因此，很可能发生了：

```text
碰撞几何按默认密度生成质量、惯量
→ 包装 Actor 时把质量改成 10 g
→ 惯量仍然保留原值
```

新窗口必须在安装版本上直接读取“包装前 / 包装后”的 mass、inertia、COM 来确认。

**需要克制的地方是：这不能直接证明所有滚转都由惯量引起。**惯量变大并不等于重力变大，修正后也可能暴露其他抓持问题。但在物理基线不自洽的情况下，继续讨论“瓶尾太重”或不停微调抓取高度，没有可靠基础。

# 五、F3 新主方案：物理参数自洽的竖放瓶体，直壁对称侧夹

## 1. 正式退役横放抓法，不再扫描第七、第八个高度

你的建议应成为主线：

```text
瓶子初始竖立
→ 从侧面水平接近
→ 对称夹住瓶身直壁
→ 竖直抬升
→ 保持瓶子朝向
→ 做 V/H 往返
→ 放回支撑面
```

F3 研究的是 `VVHH / VHVH / VHHV` 的动作顺序，**不是横躺可乐瓶的高难抓取**。

V/H 仍按桌面坐标定义，不改成“把瓶子竖起来/横过来”。三条程序仍共享第一个 V，后续顺序不同。

## 2. 先修正资产，不要把旧“参数不许动”当成正确性证明

正确的新资产流程是：

```text
按最终尺寸构建原生碰撞几何
→ 得到几何对应的 mass / COM / inertia
→ 明确目标质量或密度
→ 一致设置 mass / COM / inertia
→ 读取实际每个 shape 的材料
→ 保存实际属性
→ 再进入运动实验
```

若保持同一几何、均匀密度分布，仅将质量从 \(m_0\) 调整到 \(m_1\)，惯量应相应按：

\[
I_1 = I_0\frac{m_1}{m_0}
\]

缩放，而不是只改质量。PhysX 的质量属性工具也明确质量、惯量随密度线性缩放。citeturn902957search13

实施要求：

- 读取原值必须发生在旧 `Actor` 默认质量覆盖之前，或者使用已核实的质量属性重建接口。
- 不凭经验随手填一个更小惯量。
- 不为了通过抓取反复减质量、增摩擦。
- 在新资产版本中修正，旧失败数据不重判、不覆盖。
- 同类问题可能影响 F2 的罐子，使用同一个只读一致性检查；不要因此立即重写全部 F1/F4 资产。

**这是修复物理模型，不是放宽验收。**

## 3. 材料来源也要一次搞清楚

最新材料审计发现：

```text
场景声明：摩擦 0.5 / 0.5
mesh loader 默认：约 0.3 / 0.3，恢复系数约 0.1
```

因为 mesh 创建路径没有传入场景声明的材料，两者不是同一个来源。之前竖放尝试还在这个断言处停止，不能把它算作“竖放抓法也失败”。fileciteturn531file0L2-L2 fileciteturn545file0L2-L2

新工厂应明确传递或读取实际材料，先记录后检查。别再把“我以为是 0.5”写成事实，也别为了让断言通过去修改摩擦。

## 4. 瓶子的直径和底部可以改

对这项研究，瓶子没必要始终使用原来的尺寸。

先测实际夹爪：

```text
完全打开时的真实内侧净空
闭合时两侧接触位置
掌部与瓶身的距离
闭合扫掠空间
```

然后选一个**有开口余量、又能产生有效双侧接触**的瓶径。不要只用关节行程推测夹爪净空。

选择顺序：

1. 现有瓶体缩放到合适尺寸、初始竖放。
2. 若原生底部不能稳定站立，或瓶身曲面持续导致接触迁移，换成**平底、直壁、轮廓可控的瓶状资产**。
3. 可视几何与碰撞几何一起修改，并记录自定义资产来源。

不要给大可乐瓶贴图偷偷套一个完全不相符的小碰撞体，也不要把瓶子焊在桌面或夹爪上。

## 5. 抓直壁，不是随便抓“看起来像腰部”的位置

优先选择：

- 两侧实际接触比较对称；
- 局部表面法向适合夹持；
- 接触区域位于质心附近或适度上方；
- 掌部、手指远离桌面；
- 不夹瓶盖，不依赖没有证实的瓶颈承托。

竖放的优势是降低横躺瓶体“尾部悬出去”的不利力矩，并把夹持区域移离桌面；**但它仍依赖摩擦与有效接触，不是竖起来就必然不会滑。**

## 6. “夹紧力”应从实际驱动和接触读取

`close=0.50` 是位置指令，不是 50% 力。

SAPIEN 的关节驱动包含位置误差和速度误差项，实际接触力还受驱动上限、接触几何和物理解算影响。citeturn438302search2

新窗口应记录：

```text
drive mode
stiffness / damping / force_limit
target qpos 与 actual qpos
两侧接触法向、冲量与时间步
瓶体相对运动
```

先排除几何和物理参数问题，再决定是否需要修改控制。不能把接触冲量范数直接叫“咬合力”，也不能默认“增大 stiffness 就能解决”。

# 八、如何防止新窗口再浪费十几个小时

## 1. 第一目标不是“所有审计绿灯”，而是两个真实操作闭环

新窗口应优先交付：

```text
F2：罐子真正放进去、松开并退出的视频和原始证据。
F3：竖放瓶子真正抓起、稳定保持并完成 V/H 的证据。
```

在这两件事之前，不优先做：

```text
全量高清回放
复杂发布面板
所有历史版本重新审计
完整正式 360 manifest
模型输入出口重构
新的压缩/H-reveal/训练代码
```

这些并非没价值，而是此刻不是瓶颈。

## 2. 每次失败必须改变决策，而不是只增加文件

一次失败后明确回答：

```text
场景/几何不成立？
模型与实际不一致？
目标不可达？
规划路径碰撞？
执行跟踪失败？
抓持不稳定？
保存或验收接口出错？
```

没有新证据、没有修正，不能对相同确定性输入反复重跑。

同一主方案经过少量有根据的修订仍失败，就切换预先规定的备选资产设计。**不要再用更多高度、更多毫米级改动无限延长同一失败方案。**

## 3. 先测真正的入口

测试必须覆盖：

```text
建场景
→ 属性读取
→ current/anchor/trace 初始化
→ planner
→ action
→ 保存
→ verifier
→ cleanup
```

不能又只测 `verify()`、`sequence()` 的 mock，然后实际运行才发现 `scene.trace` 或相机/属性字段没初始化。

## 4. 调试视频实时录一份即可

下一阶段只录足以看清操作的单个外部视角，标注：

```text
run ID
当前阶段
实际 step
最终成功/失败原因
```

保持原数据相机和 raw 规范。成功模板需要展示时再做高清回放，不让多视角重渲染再次占据主工作线。

## 5. 不承诺“再两小时一定完成”，但要设置工作停损点

我不再给没有实测支撑的总完成时间。

但新窗口可以执行一个明确纪律：**每个工作块结束时，必须产生新的实际物理结果、明确的几何否决，或修掉能复现的入口错误。不能连续几个小时只增加审核文字而没有改变可执行能力。**

若一个库接口问题开始吞噬大量时间，优先采用该版本已经工作过的简单入口，不为了架构漂亮再重构整套系统。
