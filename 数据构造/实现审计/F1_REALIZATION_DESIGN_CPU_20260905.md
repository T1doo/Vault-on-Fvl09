# F1 invariance realizations: CPU design only

Existing five development roots and fifteen r_pc trajectories remain immutable. No GPU collection, promotion, Stage 1 or formal approval is supplied by this document.

Each intended formal root still needs three real successful realizations per candidate: r_pc, r_inv_path, r_inv_motion. Retain the original three candidates and full anchor/current. Each new realization must reference root ID, candidate program semantic hash, current/anchor hashes, executing arm, primary 250-Hz action layout and its immutable source r_pc receipt.

r_inv_path changes only an explicitly frozen approach/grasp/transport path or planner seed. The normal instruction, selected object, common destination, executing arm, goal predicates and operation order remain unchanged. Persist the new real trajectory and planner/reset evidence; copied or perturbed r_pc arrays do not count.

r_inv_motion changes only a preregistered speed/duration/pause schedule within the same operation order and arm. It must be a separate real rollout. A resampled view of an existing trajectory cannot satisfy the realization count. Physical stationarity/contact/event verifiers still evaluate the realized timeline.

Pairing receipt fields: root_id, scene_family_id, split, candidate_semantic_sha256, realization_type, source_r_pc_receipt_sha256, same_current_sha256, anchor_equivalence_receipt, implementation_source_sha256, frozen_variation_spec_sha256, primary_frequency_hz=250, action_layout_version, raw_integrity_receipt, verifier_receipt, failure_history. Every trajectory remains in its root's split.

Event-start alignment uses the real anchor time and measured event boundaries. Preserve both raw sample indices and physical seconds. Never retime raw to create apparent shared-prefix equality; free-path trajectory-invariance cohorts stay separate from prefix-controlled H/P cohorts.

Root acceptance checks a 3-candidate × 3-realization matrix: exactly nine unique real trajectory IDs, nine valid raw receipts and family verifiers, current/anchor equivalence, cleanup and failure history, and one shared candidate universe. Duplicate raw identifiers or absent cells reject the root. Partial successes stay outside the formal denominator.

Before execution, separately review the exact variation values, finite per-root planner/scene/time budgets, stop conditions, and pilot-promotion eligibility. This design intentionally supplies no guessed numerical runtime budget and no test or validation roots.
