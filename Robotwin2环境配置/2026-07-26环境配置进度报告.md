## 1. RoboTwin 2 是什么（背景）

RoboTwin 2 是一个**机器人操作仿真平台**。可以把它理解成一个"机器人的电子游戏世界"：

- 里面有一个双臂机器人（默认是 `aloha-agilex`）、桌子、各种物体（瓶子、锤子、积木……）。
- 你给它一个任务（比如"用锤子敲积木"`beat_block_hammer`），它会：
  1. 用**运动规划**算法（CuRobo）算出机械臂怎么动；
  2. 用**物理引擎**（SAPIEN/PhysX）模拟真实的碰撞、抓取；
  3. 用**渲染**（把 3D 场景画成相机照片，靠显卡的 Vulkan/光线追踪）生成"机器人摄像头看到的画面"；
  4. 把整个过程的**动作 + 多路摄像头画面**存成数据文件。
- 这些数据可以拿去**训练 AI 策略模型**（ACT / DP / DP3 / RDT / Pi0 等），让 AI 学会自己操作机器人。

一句话：**RoboTwin 2 = 造数据 + 训练机器人 AI 的仿真工厂。**

## 4. 最大的坑：坏显卡 GPU 2（重点，容易踩）

### 4.1 现象
服务器有 8 张显卡（RTX 3090），编号 0~7。其中**物理第 2 号卡（GPU 2）坏了**：
`nvidia-smi` 里它的风扇、功耗显示 `ERR!`，驱动标记它 `Reset Required`（需要重置）。
这一点**已经和师哥/管理员求证确认**，短期内不会修。

### 4.2 为什么它会"连累"其他好卡？
这是最反直觉的地方：**只要这张坏卡还在被系统枚举，它会把整个显卡初始化"带崩"**：
- 用 PyTorch 时：8 张卡全可见 → `torch.cuda.is_available()` 直接是 `False`（等于一张都用不了）。
- 渲染时：NVIDIA 的 Vulkan 在创建渲染设备时直接失败 → 画面渲染不出来（就是之前一直卡住的 `Render Error`）。

我们通过"一张一张卡单独测"确认：**只有 GPU 2 坏，其他 7 张（0、1、3、4、5、6、7）全好。**

### 4.3 怎么解决的（零成本、不改代码、不修硬件）
关键办法：**用 `CUDA_VISIBLE_DEVICES` 把 GPU 2 藏起来，只让程序看到 7 张好卡。**
- CUDA 藏掉坏卡后：7 张卡全部可用 ✅
- 渲染时 SAPIEN 会**根据 CUDA 能看到的卡去选渲染显卡**，所以坏卡一藏，渲染也跟着恢复 → `Render Well` ✅

我们已经把"屏蔽 GPU 2"**写进了激活脚本**，以后一激活环境就自动只用 7 张好卡，不用每次手动设。
用的是显卡的**稳定 UUID**（而不是编号），这样即使服务器重启后编号变了，也不会误伤好卡。

> ⚠️ **重要注意**：官方的采集脚本 `collect_data.sh` 会用**物理编号**强制指定显卡。
> 所以你手动采集时，`gpu_id` 只能填好卡的编号（0、1、3、4、5、6、7），**绝对不能填 2**。

### 4.4 一个不用管的"假报错"
系统命令 `vulkaninfo` 仍然会报错——因为它会去枚举所有卡（包括坏的 GPU 2）。
**这个报错可以忽略**，它不代表我们的渲染不能用。判断渲染是否正常，**只看官方 `test_render.py` 是否输出 `Render Well`**。

## 5. 怎么使用这个 RoboTwin 2 环境（手把手）

### 第 1 步：激活环境（每次开新终端都要做）
```bash
source /bigbig_nfs_share/lijunhui/Robotwin2/config/activate_robotwin2.sh
```
这一步会自动：切换到项目专用 Python、指定项目 CUDA、把所有缓存指向项目内、**自动屏蔽坏卡 GPU 2**。

### 第 2 步：确认环境正常（可选自检）
```bash
# 看能用几张卡，应显示 True 和 7
python -c 'import torch; print(torch.cuda.is_available(), torch.cuda.device_count())'

# 测渲染，应输出绿色的 Render Well
cd /bigbig_nfs_share/lijunhui/Robotwin2/project/RoboTwin
python script/test_render.py
```

### 第 3 步：采集一个任务的数据
命令格式：`bash collect_data.sh <任务名> <配置名> <显卡编号>`
```bash
cd /bigbig_nfs_share/lijunhui/Robotwin2/project/RoboTwin

# 先只读看一眼哪张卡空闲（不要占用别人正在用的卡）
nvidia-smi --query-gpu=index,memory.used,utilization.gpu --format=csv,noheader

# 例：用空闲的 3 号好卡，采集"敲积木"任务，用干净场景配置
bash collect_data.sh beat_block_hammer demo_clean 3
```
- `<任务名>`：约 50 个可选，如 `beat_block_hammer`、`open_laptop`、`lift_pot`、`handover_block`……
  （完整列表在 `project/RoboTwin/envs/` 目录下的 `.py` 文件名）
- `<配置名>`：`demo_clean`（干净场景，50 条）、`demo_randomized`（随机化场景）。
  想先小规模试，可用我们做的 `demo_clean_smoke`（只 3 条）。
- `<显卡编号>`：填空闲的好卡编号，**别填 2**。

### 第 4 步：数据存在哪、长什么样
数据存到：`project/RoboTwin/data/<任务名>/<配置名>/`，里面：
- `data/episodeN.hdf5`：核心数据。每条包含 4 路摄像头 RGB 画面 + 关节动作 + 末端位姿。
- `video/episodeN.mp4`：可视化小视频，可以直接点开看机器人在干嘛。
- `instructions/episodeN.json`：这条数据对应的语言指令。

### 常见坑速查
| 问题 | 原因 / 解决 |
|---|---|
| `torch.cuda.is_available()` 是 False | 没激活环境，或手动设了 `CUDA_VISIBLE_DEVICES` 且包含了坏卡 2 |
| 渲染报 `Render Error` | 同上；确认已 source 激活脚本，让它自动屏蔽 GPU 2 |
| `vulkaninfo` 报错 | 正常，忽略它，以 `test_render.py` 为准 |
| 采集特别慢 | 光追渲染较重属正常；先用 `demo_clean_smoke`（3 条）试跑 |
| 想换卡跑 | 采集时把 `gpu_id` 换成别的空闲好卡编号（0/1/3/4/5/6/7） |
