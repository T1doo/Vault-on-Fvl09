==疑问：一开始要不要randomized？==
若一开始同时随机背景、杂物、灯光与桌高，失败时（不能根据future action正确判断intent），很难判断是 future 机制、视觉鲁棒性还是 planner/snapshot 出了问题。我觉得先easy好一些，后面再上randomized？

#### 1.Mouse 三目标放置
| 官方任务                 | 意图             |
| -------------------- | -------------- |
| `place_mouse_pad`    | 把 mouse 放到垫子上  |
| `place_object_scale` | 把 mouse 放到电子秤上 |
| `place_object_stand` | 把 mouse 放到展示架上 
当前桌面完全相同：  
**mouse + pad + scale + stand + 若干干扰物**
三个隐藏 intent：
`y1`：mouse → pad  
`y2`：mouse → scale  
`y3`：mouse → stand
可以做到：**只给很短 future action → 还不知道最终去哪，future action 给得越来越长 → 目标逐渐暴露**

#### 2.三物体“排序 / 堆叠”任务族
|官方任务|意图|
|---|---|
|`blocks_ranking_rgb`|RGB 顺序排列|
|`blocks_ranking_size`|按大小排列|
|`stack_blocks_three`|三块积木堆起来|
统一场景为：红色小块+绿色中块+蓝色大块+干扰物...
同一个 snapshot 下：
`y1`：按 RGB 排成一排
`y2`：按尺寸排成一排
`y3`：堆成一座塔
可以做到验证future action不只是和1一样告诉模型物体最终去了哪里，而是更深一层的机器人正在执行什么“行为”
需要对官方任务配置稍微统一一下，让三种任务使用**严格相同的三个 block 初始状态**，不能分别随机初始化。
#### 3.Stack Blocks 长共享前缀多分支
|                      | Intent | 任务                     |
| -------------------- | ------ | ---------------------- |
| `stack_blocks_two`   | `y1`   | 只把绿块堆到红块上，然后结束         |
| `stack_blocks_three` | `y2`   | 先把绿块堆到红块上，然后继续把蓝块堆到绿块上 |
开始时固定红块 + 绿块 + 蓝块，相同current，==y1和y2前半段轨迹完全一样！==
```
                     ┌→ 停止
初始状态 → 抓绿块 → 堆到红块
                     └→ 抓蓝块 → 堆到绿块
```

==进一步升级M=3：==

| 阶段      | `y1：堆三层`           | `y2：Blue 放左侧`      | `y3：Blue 放右侧`      |
| ------- | ------------------ | ------------------ | ------------------ |
| 当前状态    | Red + Green + Blue | Red + Green + Blue | Red + Green + Blue |
| 第一阶段    | Green → Red        | Green → Red        | Green → Red        |
| 第二阶段前半段 | 抓 Blue             | 抓 Blue             | 抓 Blue             |
| 真正分叉    | Blue → Green       | Blue → Left        | Blue → Right       |
| 最终结果    | 三层堆叠               | Blue 在左侧           | Blue 在右侧           |

**共享前缀很长，分叉点晚**，只有 future action 再往后，出现Blue 开始向 Green / Left / Right 移动，==看到多长的H==，才能识别真正的intent

### 轨迹文本标注的格式？

```json
data/<task>/<setting>/
├── data/
│   ├── episode0.hdf5
│   ├── episode1.hdf5
│   └── ...
│
├── instructions/
│   ├── episode0.json
│   ├── episode1.json
│   └── ...
│
├── video/
│   ├── episode0.mp4
│   └── ...
│
├── _traj_data/
├── scene_info.json
└── seed.txt
```
也就是说
```
episode0.hdf5  ← 机器人轨迹本身
episode0.json  ← 这条轨迹对应的语言描述
episode0.mp4   ← 可视化视频
```
HDF5 本身没有语言字段，语言单独存在`instructions/episodeN.json`。
每条json的内容：
```
{
  "seen": ["<多条 seen 英文指令>"], //训练分布内语言
  "unseen": ["<多条 unseen 英文指令>"] //未见过的语言表达，用来测试语言泛化
}
```
https://robotwin-platform.github.io/doc/usage/description.html?utm_source=chatgpt.com
从huggingface上下载的`click_bell`任务，==seen和unseen各有100条==

https://github.com/RoboTwin-Platform/RoboTwin/blob/bf44be51cf5717a5595ce59447f2cf5263d2aa95/description/task_instruction/click_bell.json
